# Plan: SEO Completo para Bien Hecho

## Contexto

Bien Hecho tiene dos productos:
1. **bien-hecho.vercel.app** — Herramienta pública de PDF de presupuestos (HTML estática, ya tiene SEO básico)
2. **bien-hecho-web/** — App CRM/dashboard Next.js 15 (requiere auth, sin SEO configurado)

El plan cubre ambos. El foco principal es el **Next.js app** ya que es donde está el código que controlamos.

---

## Cambios a Implementar

### 1. Root Layout — MetadataBase + Template + Icons
**Archivo:** `src/app/layout.tsx`

**Qué cambiar:**
- Agregar `metadataBase: new URL("https://bien-hecho.vercel.app")` al metadata export
- Cambiar `title` de string plano a objeto con `template` y `default`:
  ```ts
  title: {
    default: "Bien Hecho — CRM para freelancers",
    template: "%s | Bien Hecho",
  }
  ```
- Agregar `icons` al metadata:
  ```ts
  icons: {
    icon: "/icon.svg",
    apple: "/apple-touch-icon.png",
  }
  ```
- Agregar `openGraph` y `twitter` defaults al metadata
- Eliminar el `<head />` vacío (Next.js App Router lo maneja automáticamente con el metadata export)

**Por qué:**
- `metadataBase` es obligatorio para que las URLs absolutas de OG/Twitter se resuelvan correctamente
- `title.template` evita hardcodear "Bien Hecho - X" en cada página; cada página solo pone su nombre y el layout agrega el sufijo
- `icons` configura favicon y apple-touch-icon sin tocar HTML manualmente
- `<head />` vacío es innecesario y genera un tag `<head>` vacío en el HTML

### 2. Robots.ts — Bloquear páginas internas
**Archivo nuevo:** `src/app/robots.ts`

**Contenido:**
```ts
import type { MetadataRoute } from "next";

export default function robots(): MetadataRoute.Robots {
  return {
    rules: [
      {
        userAgent: "*",
        allow: "/",
        disallow: ["/(auth)/", "/(dashboard)/"],
      },
    ],
    sitemap: "https://bien-hecho.vercel.app/sitemap.xml",
  };
}
```

**Por qué:**
- El dashboard requiere login — indexar esas páginas causa contenido duplicado y confunde a Google
- Las páginas de auth (/login, /register, /recover-password) no aportan valor SEO
- El `sitemap` en robots.txt le dice a Google dónde encontrar el sitemap
- `allow: "/"` permite que páginas futuras (landing, blog) se indexen

---

### 3. Sitemap.ts — Solo páginas públicas
**Archivo nuevo:** `src/app/sitemap.ts`

**Contenido:**
```ts
import type { MetadataRoute } from "next";

export default function sitemap(): MetadataRoute.Sitemap {
  const baseUrl = "https://bien-hecho.vercel.app";

  return [
    {
      url: baseUrl,
      lastModified: new Date(),
      changeFrequency: "monthly",
      priority: 1,
    },
    {
      url: `${baseUrl}/login`,
      lastModified: new Date(),
      changeFrequency: "monthly",
      priority: 0.3,
    },
    {
      url: `${baseUrl}/register`,
      lastModified: new Date(),
      changeFrequency: "monthly",
      priority: 0.3,
    },
  ];
}
```

**Por qué:**
- El sitemap le dice a Google qué páginas existen y cuán importantes son
- Incluimos login/register porque son las únicas rutas públicas visibles
- Las páginas del dashboard no van porque requieren auth (robots.txt ya las bloquea)
- `priority: 1` para la homepage, `0.3` para auth (baja prioridad)
- `changeFrequency: "monthly"` porque el contenido no cambia frecuentemente

### 4. Auth Layout — Noindex
**Archivo:** `src/app/(auth)/layout.tsx`

**Qué cambiar:**
- Agregar export de metadata con robots noindex:
```ts
export const metadata: Metadata = {
  robots: {
    index: false,
    follow: true,
  },
};
```

**Por qué:**
- Doble protección: robots.txt bloquea + meta tag noindex en la página
- Google puede ignorar robots.txt si encuentra los links en otro sitio
- `follow: true` permite que los links pasen link equity aunque la página no se indexe
- Es la práctica estándar para páginas de login/registro en SaaS

---

### 5. Dashboard Layout — Noindex
**Archivo:** `src/app/(dashboard)/layout.tsx`

**Qué cambiar:**
- Agregar export de metadata con robots noindex:
```ts
export const metadata: Metadata = {
  robots: {
    index: false,
    follow: true,
  },
};
```

**Por qué:**
- El dashboard es contenido privado que requiere autenticación
- Si Google lo indexa, usuarios ven contenido que no pueden acceder → mala experiencia
- Doble protección junto con robots.txt

### 6. Auth Pages — Metadata específica
**Archivos:** 4 páginas en `(auth)/`

Cada página recibe metadata propia:
- **login/page.tsx**: `title: "Iniciar Sesión"`, `description: "Accedé a tu cuenta de Bien Hecho"`
- **register/page.tsx**: `title: "Crear Cuenta"`, `description: "Registrate gratis en Bien Hecho"`
- **recover-password/page.tsx**: `title: "Recuperar Contraseña"`, `description: "Restablecé tu contraseña de Bien Hecho"`
- **update-password/page.tsx**: `title: "Actualizar Contraseña"`, `description: "Cambiala tu contraseña de Bien Hecho"`

**Por qué:**
- Heredan el título root "Bien Hecho — CRM para freelancers" que no es descriptivo
- Cada página tiene un título específico que describe su función
- Aunque estén noindex, los títulos correctos mejoran la experiencia de usuario (aparecen en pestaña del browser)

### 7. Dashboard Pages — Metadata específica
**Archivos:** Páginas en `(dashboard)/` que aún no tienen metadata

- **page.tsx** (dashboard): `title: "Dashboard"`
- **tareas/page.tsx**: `title: "Tareas"`
- **tareas/[id]/page.tsx**: `title: "Detalle de Tarea"` (luego será `generateMetadata` con el título de la tarea)
- **trabajos/nuevo/page.tsx**: `title: "Nuevo Trabajo"`
- **trabajos/[id]/page.tsx**: `title: "Detalle de Trabajo"`
- **trabajos/[id]/materiales/page.tsx**: `title: "Materiales"`
- **trabajos/[id]/pagos/page.tsx**: `title: "Pagos"`
- **agenda/page.tsx**: `title: "Agenda"`
- **ajustes/perfil/page.tsx**: `title: "Editar Perfil"`

**Por qué:**
- Cada página debe tener un título descriptivo en la pestaña del browser
- Aunque estén noindex, los títulos ayudan al usuario a identificar la página
- Prepara la estructura para cuando se quieran usar `generateMetadata` con datos dinámicos

### 8. Manifest.ts — Mejorar iconos
**Archivo:** `src/app/manifest.ts`

**Qué cambiar:**
- Agregar iconos raster para PWA (192x192 y 512x512)
- Agregar `maskable` purpose
- Actualizar `background_color` para que coincida con el tema

**Por qué:**
- El manifest actual solo tiene SVG, que no funciona en todos los browsers para instalación PWA
- Android necesita raster icons (192x192 mínimo) para el prompt de instalación
- `maskable` permite que el icono se adapte a la forma del device

**Nota:** Necesitamos generar los PNGs raster desde el SVG. Se puede hacer con herramientas como `pwa-asset-generator` o manualmente.

### 9. Public Assets — Favicon + Apple Touch Icon + OG Image
**Archivos nuevos en `public/`:**
- `apple-touch-icon.png` (180x180) — generado desde icon.svg
- `og-image.png` (1200x630) — imagen de preview para redes sociales

**Por qué:**
- `apple-touch-icon.png` es requerido para iOS home screen
- `og-image.png` es la imagen que se muestra al compartir en WhatsApp/Twitter/Facebook
- Sin OG image, las previews se ven genéricas o rotas

La imagen `og-image.png` necesita un diseño que represente la marca. Opciones:
1. Generar una imagen simple con el logo + texto "Bien Hecho — CRM para freelancers"
2. Usar una herramienta como Vercel OG Image Generation
3. Diseñar una imagen más elaborada

**Recomendación:** Empezar con una imagen simple (logo + texto sobre fondo verde) y mejorarla después.
