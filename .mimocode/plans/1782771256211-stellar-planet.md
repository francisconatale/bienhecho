# Plan: Migración a Supabase Single-Tenancy

## Estado Actual

El proyecto ya tiene:
- Paquetes Supabase instalados (`@supabase/ssr`, `@supabase/supabase-js`)
- Clientes Supabase configurados (`src/utils/supabase/`)
- **8 services** usando Supabase CRUD (clients, jobs, tasks, visits, materials, cobros, transacciones, task-photos)
- React Query para data fetching
- Auth basada en localStorage (`user-store.ts`) - **NO usa Supabase Auth**

**Problemas detectados:**
1. No hay `middleware.ts` raíz para refrescar sesiones
2. La función middleware en `utils/supabase/middleware.ts` retorna solo response, no el client
3. Variable de entorno usa nombre no estándar (`PUBLISHABLE_KEY` en vez de `ANON_KEY`)
4. No hay columnas `user_id` en las tablas
5. No hay RLS policies configuradas

---

## Arquitectura Single-Tenancy con Supabase

```
┌─────────────────────────────────────────────┐
│  Next.js Middleware (middleware.ts)          │
│  - Refresca sesión Supabase                │
│  - Redirige a /login si no hay sesión       │
└─────────────────┬───────────────────────────┘
                  │
┌─────────────────▼───────────────────────────┐
│  Supabase Auth                              │
│  - Registro con email/password              │
│  - Login/Logout                             │
│  - JWT con user_id                          │
└─────────────────┬───────────────────────────┘
                  │
┌─────────────────▼───────────────────────────┐
│  Tablas con user_id + RLS                   │
│  - Cada usuario solo ve sus datos           │
│  - RLS: user_id = auth.uid()                │
└─────────────────────────────────────────────┘
```

## SQL Migraciones

### 001_create_perfiles.sql
```sql
CREATE TABLE perfiles (
  id UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  nombre TEXT NOT NULL,
  rubro TEXT,
  created_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE perfiles ENABLE ROW LEVEL SECURITY;

CREATE POLICY "usuarios_su_perfil" ON perfiles
  FOR ALL USING (id = auth.uid());
```

### 002_add_user_id.sql
```sql
-- Agregar user_id a cada tabla
ALTER TABLE clientes ADD COLUMN user_id UUID REFERENCES auth.users(id);
ALTER TABLE trabajos ADD COLUMN user_id UUID REFERENCES auth.users(id);
ALTER TABLE tareas ADD COLUMN user_id UUID REFERENCES auth.users(id);
ALTER TABLE visitas ADD COLUMN user_id UUID REFERENCES auth.users(id);
ALTER TABLE cobros ADD COLUMN user_id UUID REFERENCES auth.users(id);
ALTER TABLE materiales ADD COLUMN user_id UUID REFERENCES auth.users(id);
ALTER TABLE task_photos ADD COLUMN user_id UUID REFERENCES auth.users(id);
ALTER TABLE transacciones ADD COLUMN user_id UUID REFERENCES auth.users(id);

-- Nota: visita_tareas NO necesita user_id (es tabla pivote)
```

### 003_rls_policies.sql
```sql
-- Habilitar RLS en todas las tablas
ALTER TABLE clientes ENABLE ROW LEVEL SECURITY;
ALTER TABLE trabajos ENABLE ROW LEVEL SECURITY;
ALTER TABLE tareas ENABLE ROW LEVEL SECURITY;
ALTER TABLE visitas ENABLE ROW LEVEL SECURITY;
ALTER TABLE cobros ENABLE ROW LEVEL SECURITY;
ALTER TABLE materiales ENABLE ROW LEVEL SECURITY;
ALTER TABLE task_photos ENABLE ROW LEVEL SECURITY;
ALTER TABLE transacciones ENABLE ROW LEVEL SECURITY;

-- Policies para clientes
CREATE POLICY "usuarios_sus_clientes" ON clientes
  FOR ALL USING (user_id = auth.uid());

-- Policies para trabajos
CREATE POLICY "usuarios_sus_trabajos" ON trabajos
  FOR ALL USING (user_id = auth.uid());

-- Policies para tareas
CREATE POLICY "usuarios_sus_tareas" ON tareas
  FOR ALL USING (user_id = auth.uid());

-- Policies para visitas
CREATE POLICY "usuarios_sus_visitas" ON visitas
  FOR ALL USING (user_id = auth.uid());

-- Policies para cobros
CREATE POLICY "usuarios_sus_cobros" ON cobros
  FOR ALL USING (user_id = auth.uid());

-- Policies para materiales
CREATE POLICY "usuarios_sus_materiales" ON materiales
  FOR ALL USING (user_id = auth.uid());

-- Policies para task_photos
CREATE POLICY "usuarios_sus_photos" ON task_photos
  FOR ALL USING (user_id = auth.uid());

-- Policies para transacciones
CREATE POLICY "usuarios_sus_transacciones" ON transacciones
  FOR ALL USING (user_id = auth.uid());

-- Policies para visita_tareas (acceso indirecto via visita)
CREATE POLICY "usuarios_visita_tareas" ON visita_tareas
  FOR ALL USING (
    EXISTS (
      SELECT 1 FROM visitas
      WHERE visitas.id = visita_tareas.visita_id
      AND visitas.user_id = auth.uid()
    )
  );
```

## Verificación

1. **Registro**: Crear usuario nuevo → redirige a home → datos en tabla `perfiles`
2. **Login**: Login con credenciales → sesión activa → datos visibles
3. **Aislamiento**: Usuario A no ve datos de Usuario B
4. **Logout**: Cerrar sesión → redirige a `/login`
5. **Persistencia**: Refrescar página → sesión se mantiene

---

## Notas

- Se usa el nombre de variable `NEXT_PUBLIC_SUPABASE_ANON_KEY` (estándar Supabase)
- El middleware raíz es crítico para mantener la sesión viva
- RLS es la capa de seguridad principal - los services son un refuerzo
- `visita_tareas` usa subquery para RLS (no tiene user_id directo)
